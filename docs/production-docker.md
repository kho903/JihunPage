# Production Docker Environment

## Overview

The project prvides separate Docker configurations for development and production-oriented local execution.

The development environment runs Spring Boot through Gradle `bootRun` and serves React through the Vite development server.

The production-oriented environment builds immutable application images:

- The backend runs an executable Spring Boot JAR with `java -jar`
- The frontend is built as static files and served by Nginx
- Source code is not mounted into the application cotainers
- Blue and Green backend environments use the same production backend image
- MySQL and Redis remain shared between the backend environments

The production-oriented Compose file is:

```text
compose.prod.yaml
```

This environment is intended to reproduce a deployment-like structure locally before AWS and CI/CD are added.

## Architecture

```text
Browser
   │
   ▼
External Nginx :80
   ├── /          → frontend:80
   ├── /api/      → active backend environment
   └── /uploads/  → active backend environment

                     ┌── backend-blue:8080
Active upstream ─────┤
                     └── backend-green:8080

Backend environments
   ├── MySQL
   ├── Redis Session
   └── Shared gallery upload directory
```

Only one backend environment receives user traffic through Nginx at a time.

The initial active environment is Blue.

## Development and Production Differences

| Category              | Development                  | Production-oriented   |
| :-------------------- | :--------------------------- | :-------------------- |
| Compose file          | `compose.yaml`               | `compose.prod.yaml`   |
| Backend execution     | Gradle `bootRun`             | `java -jar`           |
| Backend source mount  | Included                     | Not included          |
| Gradle cache mount    | Included                     | Not included          |
| Frontend execution    | Vite development server      | Nginx static server   |
| Frontend source mount | Included                     | Not included          |
| HMR                   | Enabled                      | Disabled              |
| React output          | Generated by Vite at runtime | Prebuilt `dist` files |
| External Nginx config | `default.dev.conf`           | `default.prod.conf`   |
| Blue-Green switching  | Supported                    | Supported             |

## Backend Production Image

The backend uses a multi-stage Docker build.

```text
Build stage
-> Java 21 JDK
-> Gradle Wrapper
-> Spring Boot bootJar
-> Executable JAR

Runtime stage
-> Java 21 JRE
-> Copy app.jar
-> Run as a non-root user
-> java -jar /app/app.jar
```

Build the backend image:

```bash
docker build \
  -t jihunpage-backend:prod \
  ./backend
```

Inspect the image entry point:

```bash
docker image inspect \
  jihunpage-backend:prod \
  --format '{{json .Config.Entrypoint}}'
```

Expected result:

```text
["java","-jar","/app/app.jar"]
```

Inspect the runtime user:

```bash
docker image inspect \
  jihunpage-backend:prod \
  --format '{{.Config.User}}'
```

Expected result:

```text
spring:spring
```

The runtime image does not require:

- Backend source code
- Gradle Wrapper
- Gradle build tools
- Development source mounts
- Gradle cache mounts

## Frontend Production Image

The frontend also uses a multi-stage Docker build.

```text
Build stage
-> Node
-> npm ci
-> npm run build
-> Generate dist files

Runtime stage
-> Nginx
-> Copy dist files
-> Serve static React application
```

Build the frontend image:

```bash
docker build \
  -t jihunpage-frontend:prod \
  ./frontend
```

Inspect the runtime command:

```bash
docker image inspect \
  jihunpage-frontend:prod \
  --format '{{json .Config.Cmd}}'
```

Expected result:

```bash
docker build \
  -t jihunpage-frontend:prod \
  ./frontend
```

Inspect the runtime command:

```bash
docker image inspect \
  jihunpage-frontend:prod \
  --format '{{json .Config.Cmd}}'
```

The frontend Nginx configuration includes an SPA fallback:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

This allows React Router routes such as `/login`, `/signup`, and `/gallery` to work after a direct browser refresh.

## Environment Configuration

The production-oriented environment reads database credentials fron the project root `.env` file.

Required variables:

```dotenv
MYSQL_DATABASE=
MYSQL_USER=
MYSQL_PASSWORD=
MYSQL_ROOT_PASSWORD=
```

The `.env` file must not be committed.

The backend containers receive their application settings through environment variables.

```text
SPRING_DATASOURCE_URL
SPRING_DATASOURCE_USERNAME
SPRING_DATASOURCE_PASSWORD
SPRING_DATA_REDIS_HOST
SPRING_DATA_REDIS_PORT
APP_INSTANCE_NAME
```

## Switch from Development to Production-Oriented Execution

The development and production-oriented environments expose the same host ports, so they should not run at the same time.
Stop the development environment:

```bash
docker compose down
```

Do not use `-v` unless the development database and Redis data should also be deleted.
Start the production-oriented environment:

```bash
docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  up -d --build
```

Check the service state:

```bash
docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  ps
```

## Basic Verification

### Main page

```bash
curl -I http://localhost
```

Expected result:

```text
HTTP/1.1 200 OK
Content-Type: text/html
```

### Active backend

```bash
curl -si http://localhost/api/health \
  | grep -Ei 'HTTP/|x-backend-instance:'
```

Initial expected result:

```text
HTTP/1.1 200
X-Backend-Instance: backend-blue
```

### Direct backend checks

Blue:

```bash
curl -si http://localhost:8081/api/health \
  | grep -Ei 'HTTP/|x-backend-instance:'
```

Green:

```bash
curl -si http://localhost:8082/api/health \
  | grep -Ei 'HTTP/|x-backend-instance:'
```

### React Router refresh

```bash
curl -I http://localhost/login
curl -I http://localhost/signup
curl -I http://localhost/gallery
```

Each route should return HTTP `200`.

## Shared Redis Session Verification

Create a cookie file:

```bash
COOKIE_FILE=/tmp/jihunpage-prod-session.txt

rm -f "$COOKIE_FILE"
```

Log in while Blue is active:

```bash
curl -si \
  -c "$COOKIE_FILE" \
  -H "Content-Type: application/json" \
  -d '{
    "userid": "YOUR_USER_ID",
    "userpwd": "YOUR_PASSWORD"
  }' \
  http://localhost/api/auth/login \
  | grep -Ei 'HTTP/|set-cookie:|x-backend-instance:'
```

Verify authentication:

```bash
curl -si \
  -b "$COOKIE_FILE" \
  http://localhost/api/auth/me \
  | grep -Ei 'HTTP/|x-backend-instance:'
```

Expected result:

```text
HTTP/1.1 200
X-Backend-Instance: backend-blue
```

Switch traffic to Green:

```bash
cp \
  nginx/upstreams/backend-green.conf \
  nginx/upstreams/active-backend.conf
```

Validate and reload the production Nginx container:

```bash
docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  exec nginx nginx -t

docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  exec nginx nginx -s reload
```

Reuse the existing session cookie:

```bash
curl -si \
  -b "$COOKIE_FILE" \
  http://localhost/api/auth/me \
  | grep -Ei 'HTTP/|x-backend-instance:'
```

Expected result:

```text
HTTP/1.1 200
X-Backend-Instance: backend-green
```

This verifies the following flow:

```text
Blue creates is stored in Redis
-> Session is stored in Redis
-> Nginx switches traffic to Green
-> Green reads the same Redis session
-> Authentication remains valid
```

Restore Blue after verification:

```bash
cp \
  nginx/upstreams/backend-blue.conf \
  nginx/upstreams/active-backend.conf

docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  exec nginx nginx -t

docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  exec nginx nginx -s reload
```

## Verify Runtime Mounts

The production backend containers should mount only the gallery upload directory.

```bash
docker inspect \
  "$(docker compose \
      -p jihunpage-prod \
      -f compose.prod.yaml \
      ps -q backend-blue)" \
  --format '{{range .Mounts}}{{println .Source "->" .Destination}}{{end}}'
```

Expected mount:

```text
backend/uploads → /app/uploads
```

The following development mounts should not exists:

```text
backend source → /app
Gradle cache → /home/gradle/.gradle
```

The production frontend should not have any source-code or `node_modules` mounts.

```bash
docker inspect \
  "$(docker compose \
      -p jihunpage-prod \
      -f compose.prod.yaml \
      ps -q frontend)" \
  --format '{{json .Mounts}}'
```

Expected result:

```text
[]
```

## Stop the Production-Oriented Environment

```bash
docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  down
```

The MySQL and Redis named volumes remain available.

To remove the production-oriented database and Redis volumes as well:

```bash
docker compose \
  -p jihunpage-prod \
  -f compose.prod.yaml \
  down -v
```

This permanently removes the local production-oriented data.

## Return to the Development Environment

After stopping the production-oriented environment:

```bash
docker compose up -d
```

The development environment uses its own MySQL and Redis named volumes, so its data is separate from the production-oriented environment.

## Known Limitations

This configuration reproduces a production-like structure locally, but it is not yet a complete production deployment.
It does not yet include:

- Remote Docker image registry
- Versioned image tags
- Deployment scripts
- GitHub Actions
- AWS deployment
- HTTPS
- Domain configuration
- External object storage
- Managed MySQL or Redis
- Database migration automation
- Automatic health-check retries
- Automatic rollback
